## [Unreleased]

### Added

- `.gitattributes` created at repo root with `reference-impl/CHANGELOG.md merge=union` — prevents merge conflicts when concurrent branches each append entries to `## [Unreleased]` in `reference-impl/CHANGELOG.md`.
- `.cloverleaf/policy-check.mjs` + `.cloverleaf/policy-probes.tsv` — a guard for `.cloverleaf/claw-drive-policy.json`, which nothing covered before. The policy ships in neither npm package, so no vitest suite sees it, and the `> /dev/null` false positive below sat there through an entire council dogfood unnoticed. The check runs 54 (tool, command → expected decision) pairs through the real `claw-drive policy-test` CLI and exits non-zero on any mismatch. It refuses to pass on a table that parses to fewer than 40 rows, or one that has lost `Bash`, `Edit` or `Write` coverage — a probe file that silently matched nothing would otherwise read exactly like a pass. Proved with 10 mutations, each shown to have landed on disk before the guard was run.
- `.github/workflows/reference-impl.yml` (`reference-impl-ci`) — `reference-impl` had no CI at all: all 1240 tests across 62 files, the three version guards among them, ran only when a human typed `npm test`. `prepublishOnly` re-runs the suite, so a broken guard could never reach npm; the exposure was that a broken commit sat green on `main` until somebody published. Two parallel jobs on Node 24.x, unfiltered on `push` and `pull_request` to `main`. The full job's order is forced rather than stylistic — `reference-impl` resolves `@cloverleaf/standard` by symlink (`package-lock.json` records `"resolved": "../standard", "link": true`) and `standard/` has no `prepare` script, so `standard` must be installed and built before `reference-impl`'s `pretest` will pass — and it ends with `npm run build`, which `npm test` never invokes and only `prepublishOnly` did. The second job runs `package-contract`, `skills` and `site-accuracy` alone: 350 tests in about half a second, needing no `standard` build, so a version-guard regression reports in seconds instead of minutes. Unfiltered deliberately — the suite is cross-cutting, `site-accuracy` reading `site/src` and `package-contract` walking every package for lockfile drift, so a `reference-impl/**` filter would blind the very guards it exists for. Node 24.x alone because it is the only runtime the suite has a measured green on, and neither package declares `engines`. Measured on `ubuntu-latest`: 1240/1240 with vitest reporting 82.93s and 87.17s across runs — roughly 2.6× **faster** than the workstation the pre-flight measurements came from (227s and 633s), so the expectation that a hosted runner would be slower was wrong. ⚠ The merge commit `30e4582` says this needed no changelog entry because workflows ship in neither package; that reasoning is inverted — this section is where the repo records its non-shipping changes, three of its entries give exactly that as the reason, and `standard.yml` itself was recorded here under `0.3.0`. Corrected here rather than by rewriting merged history. These files ship in neither npm package.
- `.github/workflows/site-check.yml` (`site-check`) — a pull request touching `site/**` got no Astro or TypeScript check in CI before merge. `site.yml` (`site-deploy`) triggers only on `push` to `main` and on `workflow_dispatch`, so the first CI run to build the site was the push that deploys it. `reference-impl-ci` already checks the site's prose on every PR through `site-accuracy`, and Cloverleaf's own QA council member runs `npm ci && npm run build` for a diff touching `site/**` (`.cloverleaf/config/qa-rules.json`) — but only when a council includes it, which in the shipped `council.json` is `delivery-full` alone, and only on the machine running that council; no CI workflow ran `astro check` or `astro build` until the deploy. The new workflow runs `npm ci` and then `npm run build` — which is `astro check && astro build`, the deploy's own command — on Node `22.x`, the version `site.yml` deploys with, for pull requests to `main` that touch `site/**` or the workflow itself. It is a separate file rather than a `pull_request` trigger on `site.yml` because that workflow's `pages` concurrency group, with `cancel-in-progress: true`, is repository-wide: a PR run would join it and cancel an in-flight deploy. Containing that inside `site.yml` means editing the file that publishes the site in several coordinated places — its concurrency group, its `pages: write` and `id-token: write` grants, and a guard on `deploy` — and the natural guard is itself a trap: `if: github.event_name == 'push'` would silently stop `workflow_dispatch` from ever deploying, where `!= 'pull_request'` would not. The `site/**` filter is safe because nothing under `site/` imports or reads outside it and `site/package.json` has no `@cloverleaf/*` dependency; the coupling runs the other way — `reference-impl`'s suite reads `site/` — which is one reason `reference-impl-ci` is unfiltered. There is no `push` trigger because `site-deploy` already runs the same install and build on every such push. Measured on `ubuntu-latest` before this file existed: the deploy's build job — the same install and build plus a one-second artifact upload — took 18–29s across its five most recent runs. Shown to fail before merge: a throwaway commit with a deliberate type error in `site/src/pages/faq.astro` turned the check red on its pull request — `astro check` reported `ts(2322)`, 1 error, and the job exited 1 in 19s — while `standard-ci` and `reference-impl-ci`, `site-accuracy` included, stayed green on that same commit; the probe was then dropped from the branch. It ships in neither npm package.
- `.github/workflows/policy-check.yml` (`policy-check`) — `.cloverleaf/policy-check.mjs` ran only when a human typed it: no workflow, test or script invoked it, so an edit to `.cloverleaf/claw-drive-policy.json` or its probe table reached `main` unchecked — `73fee1c`, a direct commit to the policy on 2026-09-26, triggered only `standard-ci` and `reference-impl-ci`. The new workflow builds claw-drive and runs the probe table through its `policy-test` CLI on `push` and `pull_request` to `main` that touch the policy, the probe table, the script or the workflow itself, daily on a schedule, and on `workflow_dispatch`. Unlike `site-check` it has a `push` trigger, and that trigger is the point: five of the six commits that ever touched those files went straight to `main` — three of the four since the check was added — where a `pull_request` trigger never fires. claw-drive is not on npm, its releases carry no assets, and `npm install github:renatodarrigo/claw-drive` exits 0 without building — claw-drive has no `prepare` script and gitignores `dist/` — leaving a binary that fails with `ERR_MODULE_NOT_FOUND`; so the job checks claw-drive out, runs `npm ci --ignore-scripts` and `npm run build`, and runs the binary once before trusting it. It builds claw-drive's `main`, not a release tag, so the check follows the engine as it develops rather than a pin that goes stale between releases — claw-drive shipped twelve tags between 2026-08-15 and 2026-09-21. The price is that the verdict no longer depends on this repo alone: the path filter covers every input here, but only the schedule can see claw-drive's `main` move, so the job logs the claw-drive commit behind each verdict, and a red run with nothing changed here means the engine changed. GitHub disables a public repository's schedules after 60 days without repository activity. The token is declared read-only rather than inherited, since the job runs code this repository does not pin; and because of the path filter the check must not become a required one as it stands — GitHub leaves a path-skipped check Pending, which blocks the pull request. Measured on `ubuntu-latest`: the job took 24s green and 22s red, of which the probes took 9–11s — against 23–49s for the same probes on the workstation the pre-flight measurements came from. Shown to fail before merge: a throwaway commit flipping one probe's expectation (`policy-probes.tsv:21`, `auto_approve` → `auto_reject`) turned the check red on its pull request — `FAIL policy-probes.tsv:21: expected auto_reject, got auto_approve`, 53/54, exit 1, with only the probe step failing — while `standard-ci` and `reference-impl-ci` stayed green on that same commit; the probe was then dropped from the branch. It ships in neither npm package.

### Fixed

- `.cloverleaf/claw-drive-policy.json`'s `_comment` described the file wrongly in four ways, and one of them asserted a closure — the strongest kind of claim, because it tells a reader not to look. It said there were **three** deliberate divergences from claw-drive's shipped starter while enumerating **four**; it claimed divergences 3 and 4 were both fixed upstream in claw-drive 1.7.3 and that "this file now matches that"; it described its own `.claw-drive/` guard as a character class when the rule is a lookbehind; and it pinned upstream at commit `b4cd9c4` / 1.7.3 when claw-drive has since released 1.10.0. Measured against the released `v1.10.0` tag: only the device-write branch is closed. The `.claw-drive/` guard **still diverges** — upstream's template has carried `(?:^|/)\.claw-drive/` unchanged from `b4cd9c4` through `v1.10.0` — so the live count is three, not two. The divergence is real but near-vestigial: the two regexes agree on every ordinary `file_path` shape and differ only for `=`-prefixed or quoted paths, which do not arise when the argument is itself the path, and the broader deny form is kept deliberately. Comment only — no rule changed, and `policy-check` passes 54/54 against the rewritten file.
- `.cloverleaf/claw-drive-policy.json`'s `_comment`, corrected twice more on 2026-09-26. `73fee1c`, committed straight to `main` with no entry here, re-measured divergence (3) — the `.claw-drive/` guard — by running upstream's template through `claw-drive policy-test` instead of reading regexes, and concluded it was "textual only -- it changes which rule fires, not what happens". That compared only the `decision` field. For quoted, `=`-prefixed and space-prefixed `file_path` arguments both policies escalate, so a human is asked either way, but upstream escalates through `escalate_default`, whose `default_action` is `approve` at severity medium, where this file's rule defaults to `reject` at severity high — and claw-drive applies the default when `decision_timeout_seconds` (3600 in both files) passes unanswered. So an unanswered call is allowed upstream and denied here, and the entry above had it right: real but near-vestigial. The same note said the `echo x > .claw-drive/sessions/y` redirect "was never open" upstream; upstream's template auto-approved it until claw-drive 1.7.3, measured against its `v1.5.3` and `v1.7.2` templates. The paragraph now says both. Comment only — every rule list is unchanged, and `policy-check` passes 54/54.
- `.cloverleaf/policy-probes.tsv` — two comments described claw-drive's upstream template as it stood when the table was written on 2026-08-11, a week before claw-drive 1.7.3 changed it, and neither was revisited. Over the device-write probes: "Upstream still has that gap; see divergence 3 in the policy's own _comment". Measured with `claw-drive policy-test` against each tag's template, upstream auto-approves `cat img >/dev/sda` at `v1.7.2` and escalates it from `v1.7.3` on; the `auto_reject` rule these probes hit is upstream's verbatim at `v1.10.1`; and divergence 3 in the `_comment` has since come to mean the `.claw-drive/` guard, while the device-write branch is recorded under CLOSED. Over the relative-path runtime-state probes: "Upstream demands `(?:^|/)\.claw-drive/`, so every row here but the ./ and absolute ones was auto-approved before the fix". 1.7.3 dropped that anchor from upstream's Bash rule, while its Edit/Write rules keep it; and even before, under the `v1.5.3` template current that day, only the relative `echo x >` row was auto-approved — `tee`, `cp`, `mv` and `sed -i` escalated to a human, with approve as the default. Both comments now say what was measured, against the tags they name. Comment only — no probe changed, and `policy-check` passes 54/54.

- `.cloverleaf/claw-drive-policy.json` — realigned on claw-drive's shipped starter (`templates/claw-drive-policy.json`), which it had diverged from by hand. The reported defect was the `auto_reject` alternative `> /dev/`, intended to catch device writes but matching the ubiquitous `> /dev/null`, so routine commands escalated at `severity: high, default_action: reject` — twice in the 2026-08-05/06 dogfood. Converging fixes that and four more holes the divergence had left open: `node -e '<anything>'` was auto-approved by a blanket `^(npm|npx|node) ` rule with no `auto_defer` list to catch it; there was no protection for claw-drive's own policy file or `.claw-drive/` runtime state; `curl … | bash` and disk-destructive ops (`dd if=`, `mkfs`, `shred`, `fdisk`) went unlisted; and `git -C <path> …` plus compound `cd … && npm …` escalated needlessly — 418 of the dogfood's 752 commands escalated, which is what made it noisy. Measured against those same 752 commands the rewrite escalates 164.
- `.cloverleaf/baselines/` — regenerated toolbar-free and reduced to the twelve images this repo's resolved UI-review config and route slugs actually reference. The tracked set had accumulated three capture regimes and was stale on every axis, not just the Astro dev toolbar the 2026-08-06 dogfood reported. Eighteen of the twenty-four images had dimensions the current config never produces: the `guide-*` images were full-page captures up to `1280×12954`, and the chromium `*-mobile` images were 500px wide against a configured 375. The three `home-*` images were named for a slug the code cannot emit — `computeAffectedRoutes` yields `/` for the home page and `slugifyRoute('/')` returns `index`, for which no baseline existed at all. The twelve `firefox/` and `webkit/` images were unreachable because the resolved config is chromium-only (`.cloverleaf/config/ui-review.json` omits `browsers`, so `applyDefaults` supplies `["chromium"]`). Only four images were both live and dimensionally current, and each diffed 5.2–8.4% against a fresh capture — five to eight times the `maxDiffRatio: 0.01` gate — dominated by a whole-page horizontal text shift from a scrollbar the old captures included, with the toolbar a small part of it. The set is now `{index,faq,guide,start} × {mobile,tablet,desktop}` for chromium, captured at the configured viewports with the toolbar disabled and verified pixel-identical across two independent capture passes; the fifteen unreachable images are deleted. These files ship in neither npm package.
- Four deliberate divergences from the upstream starter are kept, each recorded in the policy's own `_comment` and pinned by a probe. **(1)** `bash_composition: per_segment` is omitted: measured over the 752 real commands it `deny_silent`s 178 of them (175 "opaque", 3 "malformed") — refused *without* escalating to a human, ordinary heredoc `git commit` invocations among them. **(2)** Because there is no `per_segment`, the `sudo`/`su` rules are un-anchored; upstream's `^`-anchored forms rely on per-segment evaluation, so without it `cd /tmp && sudo …` fell through to the `^(set -e|cd |…)` auto-approve prefix. **(3)** and **(4)** are upstream gaps rather than cloverleaf preferences, and should flow back: the device-write branch is `>\s*/dev/(…)` rather than `> /dev/(…)`, because no shell requires a space after `>` and `cat img >/dev/sda` was therefore *auto-approved*; and the `.claw-drive/` runtime-state guards match `(?:^|(?<=[\s/'"=]))\.claw-drive/` rather than `(?:^|/)\.claw-drive/`, because upstream requires the path to start the command or follow a slash while the natural relative form follows a space — so `echo x > .claw-drive/sessions/y` was *auto-approved* too.
- `site/src/content/guide/` and `site/src/components/` — the methodology guide still described the delivery topology Slice 4 retired: a branch between a fast lane and a full pipeline, an `automated-gates` hub, `security_gate` on the three edges leaving it, and `resets_security_verdict` on the `review → automated-gates` edge that returned to it. The hub and those edges are gone; `resets_security_verdict` is gone outright; `security_gate` survives only as an optional annotation a consumer state machine may set on its own transitions. Forty-three references across seven files were corrected to the shipped model — one delivery path whose council profile is selected by `risk_class` (`delivery-fast` / `delivery-full`), with the security guarantee resting on a blocking council member and a recorded `security_review_verdict` on `council → final-gate`. Chapter 11 gains a Retired vocabulary block mapping the old terms onto the new ones. The §PATH lane sweep covered `standard/` and `reference-impl/lib` but not `site/`, which is why this survived; `reference-impl/tests/lane-vocabulary-retired.test.ts` now sweeps `site/src` too. These files ship in neither npm package.
- `site/src/` — the public site stated things the artifacts did not support, and `.github/workflows/site.yml` deploys on any push to `main` touching `site/**`, so the release push is also the moment those claims go live. The agent roster is now **nine**, matching `reference-impl/README.md`: `AgentMatrix.astro` rendered seven and named neither the Security Reviewer nor the Chair, chapter 7 said eight, and the glossary, FAQ, start page and hero all said seven — two independent "eight"s naming different sets, while "Chair" appeared nowhere on the site at all. Both missing roles now render with the conditionality the matrix already expressed for others, and each gained a chapter-7 paragraph and a glossary headword. Every Standard version string moved `0.3.0` → `0.8.0` — the footer renders on every page, so it was the most-seen false claim on the site, wrong against both the repo and the published registry by five minor versions — and its `2026-04-20` date was removed rather than refreshed, the honest value being a release date not knowable at the time. A new `reference-impl/tests/site-accuracy.test.ts` carries twenty-one assertions across three guards: every link resolves against the chapter ids `guide.astro` actually emits, every Standard version string matches `standard/package.json`, and every prose agent count matches both the rendered matrix and `reference-impl/README.md`'s agent table — the last anchored externally because internal parity alone would have stayed green through the whole drift it exists to catch. These files ship in neither npm package.

## [reference-impl 0.1.1] — 2026-04-20

Bug-fix release addressing issues surfaced by the v0.1.0 end-to-end demo and final code review.

### Fixed

- Auto-create `.cloverleaf/events/` and `.cloverleaf/feedback/` on first write (previously crashed with ENOENT in fresh consumer repos).
- `advanceStatus` is now atomic: the status event is emitted before the task file is saved, so a failed emit leaves the task unchanged. A failed save after a successful emit produces a clear "orphan event" error.
- Every write path now validates against the corresponding `@cloverleaf/standard` schema via the new `lib/validate.ts` (AJV). `saveTask`, `writeFeedback`, `emitStatusTransition`, and `emitGateDecision` throw on invalid input.
- Shared `formatReason` helper eliminates drift between the validator-input `reason` and the persisted `reason` on status-transition events.
- CLI `advance-status` now rejects `actor=system` with exit code 2 (previously silently cast to `agent`). `system` is not a valid actor for task transitions in the Standard's state machine.
- `tests/cli.test.ts` fixtures aligned with the real task + project schemas so they double as teaching examples.

### Changed

- **Branch topology:** state commits now land on `main`; feature branches (`cloverleaf/<task-id>`) carry only code. Skills handle the `git checkout main` transitions. The Reviewer never `git checkout`s — uses `git show` and `git worktree add` instead. See README "Branch topology".

### Added

- `reference-impl/lib/validate.ts` — shared AJV `validateOrThrow` helper loading all `@cloverleaf/standard` schemas once.
- `reference-impl/README.md` gains a "Branch topology" section.

## [reference-impl 0.1.0] — 2026-04-20

First release of the Cloverleaf reference implementation package.

### Added

- `@cloverleaf/reference-impl@0.1.0` — Tight-Loop reference implementation (Implementer + Reviewer) as Claude Code skills.
- Five skills: `/cloverleaf-new-task`, `/cloverleaf-implement`, `/cloverleaf-review`, `/cloverleaf-merge`, `/cloverleaf-run`.
- `lib/` TypeScript library for state + events + feedback + ID allocation.
- `install.sh` with user-level and project-local modes.
- `examples/toy-repo/` end-to-end demo.
- Targets L2 Exchange conformance of `@cloverleaf/standard@0.3.0`.

### Known gaps

- Documenter, UI Reviewer, QA, Researcher, Plan agents are stubbed (state transitions emitted, no work performed).
- No HTTP endpoints; L3 conformance deferred.

## [0.3.0] — 2026-04-20

### Added

- Conformance levels: L1 Producer, L2 Exchange, L3 Host. Every schema, validator, agent contract, state machine, and scenario is assigned to a level via `conformance/level-map.ts`.
- `--level=<1|2|3|all>` flag on the conformance runner (`npm run validate:examples -- --level=2`).
- Per-example `.meta.json` sidecars declaring which level(s) each fixture targets.
- Per-level Vitest suites: `conformance/tests/by-level/l1.test.ts`, `l2.test.ts`, `l3.test.ts`.
- `standard/docs/conformance.md` rewritten around the three-level model.
- `standard/docs/versioning.md` section on levels and SemVer.
- GitHub Actions workflow `.github/workflows/standard.yml` running tests + filtered conformance on Node 20 and 22.
- npm package metadata: `publishConfig`, `files`, `prepublishOnly`, `repository`, `homepage`, `bugs`, `license`, `keywords`.
- Repo-root `README.md`, `CHANGELOG.md`, `LICENSE` (MIT).

### Changed

- `@cloverleaf/standard` bumped to `0.3.0`.
- `standard/README.md` adds Conformance and Publish sections.
